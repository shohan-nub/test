# SparkLab pre-launch audit

18 November 2026, Asia/Dhaka. Baseline audited before the comparison section was added.

## A. Executive summary

Hold publication until the four stacked project previews are restored and the dependency check is resolved. Cards 1–4 request files absent from the repository. Each request returned HTTP 404 in production-mode Chrome. The page builds its static output, but the baseline build command exited with a Next.js security warning. The configured Next.js version also appears in two published advisories.

Local anchor targets resolved, the carousel responded to its Next control, and the stack returned to its sampled geometry on reverse scroll. The most consequential motion and loading concern is startup contention. A full-page loader depends on hydration while both autoplay videos, dozens of images and the homepage animation bundle compete for resources. On one cold 4× CPU-throttled mobile run, the loader node remained mounted until 5.37 seconds after navigation.

The baseline showed two ScrollTrigger pin spacers with standard motion and zero on a fresh reduced-motion load. The stack and collage share one homepage GSAP context, and the masonry owns a separate scoped context. This supports expected initialization for a single load. Duplicate triggers and leaked work after repeated remounts require a separate lifecycle trace. Changing the system motion preference live is also worth testing because the main homepage GSAP effect reads the preference once.

## C. Performance audit

| ID | Area | Evidence and recommendation |
| --- | --- | --- |
| P1 · High | Video startup and decode | `public/card5.mp4` is 28,811,247 bytes and `public/creative-loop.mp4` is 9,291,138 bytes. Both use `preload="auto"` and start before reaching their sections. Combined size is 38.1 MB on disk, independent of what a browser fetches initially via byte ranges. Delay network and playback until near visibility, provide a static reduced-motion state, and evaluate alternate encodes against the source quality. Keep the card video and its audio intact until a reviewed replacement exists. |
| P2 · High | Image request priority | Four missing previews return 404. The pinned collage eagerly loads ten thumbnails. The moving gallery renders 36 image elements sharing 18 unique local WebPs totaling 1,017,872 bytes on disk. Three initially visible carousel positions request eager images, and the deep masonry's first image has high priority. Reserve eager priority for the opening experience and load later sections ahead of their actual entry. Audit the technology icon CDN and remote Our Story images for slow or failed requests. |
| P3 · Medium | JS and hydration | `page.tsx` is a client component and includes multiple independent interactive sections. One cold desktop run recorded roughly 231 KB of completed script transfer by the initial sample, plus roughly 1.60 MB of completed image transfer. That observation includes transfer overhead and excludes incomplete requests. Reduce the hydrated surface for static markup in a separate refactor and profile nav-driven parent renders. Keep GSAP and ScrollTrigger where they are in active use. Resend is server-side for contact and is not a reason to remove an animation dependency. |
| P4 · Medium | CSS, GPU and painting | Fixed ambient lighting, moving tracks, the Hero SVG, stacked-card gradient layers, nav blur and multiple large shadows can be active together. This is a rendering budget concern. The audit did not attribute a specific long task to blur or a particular layer. Record a device trace before replacing these effects. Consider removing dead CSS rules only after identifying effective cascade rules at each breakpoint. |
| P5 · Medium | Stability and scrolling | A cold throttled mobile idle run produced no layout-shift entries in its first 5.5 s. Programmatic section jumps generated shift entries during pin and animation transitions. Those jumps are unsuitable for reporting a CLS score or proving a natural-scroll flicker. Recheck using a continuous input trace, after image loading and on viewport rotation. |
| P6 · High | Framework version and build | `package.json` pins Next.js 16.4.2. The baseline `npm run build` compiled, type-checked and generated routes, then exited with a security advisory prompt. `npm audit --omit=dev` flagged one direct dependency with two moderate advisories. The affected ranges include this version. The repository inspection did not establish that the conditions needed for these cache issues exist in this app. Upgrade to a patched version in a separate reviewed change and recheck production and contact behavior. [First Next.js advisory](https://github.com/advisories/GHSA-mfr8-8qww-v76h) · [Second Next.js advisory](https://github.com/advisories/GHSA-vc7v-qv4w-wrv8) |
| P7 · Low | Unreferenced media and tooling | `public/test.mp4` and `public/service-loop.mp4` have no references in `src`. They increase package storage if shipped, without contributing to initial transfer in the sampled homepage. Confirm retention and deployment requirements before removing any user assets. Existing asset-check and design-preparation scripts are build-time tools. |

## E. Priority classification

- **Critical** — A10, restore the four broken project previews before release.
- **High** — A1, bound loader blocking time. A10b and A12, address hidden focus targets and showreel motion. P1 and P2, reduce competing offscreen requests. P6, patch and recheck the framework.
- **Medium** — A2–A9, A11 and A13, plus P3–P5. Address verified cleanup and accessibility gaps first. Profile before changing timings or choosing rendering optimizations.
- **Low** — A14–A15 and P7. Refine Story, globe and asset retention once the launch checks are clear.

## F. Recommended fix plan

1. Restore the preview files for cards 1–4 and add a validation check for their exact URLs. Upgrade Next.js in a separate review and verify the production build and registry audit.
2. Correct stacked-card focus behavior and reduced-motion showreel playback. Recheck motion preferences on initial load and during the page session.
3. Defer autoplay video and distant images until they approach visibility. Re-profile a cold start, then use the measured result to choose the loader release window and verify the Hero handoff.
4. Check continuous scroll and reversal across the pinned sections on desktop and physical phones. Profile offscreen marquee work, canvas, masks and blur before changing animation curves or durations.
5. Retest carousel hover, focus, touch and rapid selection. Exercise route remounts, contact delivery in staging, and cross-browser visual behavior before publishing.

## G. Verification status

- **Code and assets inspected** — Homepage, root layout, all active homepage components and their motion styles, contact integration, package manifest, production configuration and local media references. The recommendations above are read-only audit findings.
- **Observed in production-mode Headless Chrome** — Initial loading, sampled normal and reduced-motion states, viewport bounds, counter updates, manual SEO/GEO advancement, first masonry reveal, footer canvas movement, and forward/reverse stack geometry. Four preview URLs returned 404 at all four widths. No uncaught runtime exceptions appeared in those smoke tests.
- **Timing evidence** — Loader DOM removal occurred at approximately 2.60 s on the 390 px run and 2.71 s on the tablet run. On one cold 4× CPU-throttled 390 px run, it occurred at 5.37 s, with seven long-task entries ranging from 56 to 468 ms. These are local timing samples and measure DOM presence, which can outlast visual coverage. They are not production performance targets or field metrics.
- **Pending verification** — Full screenshot and frame-by-frame visual review, precise attribution of animation jank or flicker, actual mobile device and Safari/Firefox behavior, LCP/INP/CLS in the field, repeated remounts, actual sound output, and live contact delivery. No form was submitted to the live service. The generated baseline output served the browser smoke tests despite the build command's initial security advisory exit.
